# 视觉检测调参笔记——图例/主体/列序尺（2026-09 v1→v9）

拼豆还原链路里三个自动检测的算法演进与经验总结。算法本体注释在
`lib/core/legend_detect.dart` / `lib/core/board_detect.dart`，本文只记
**方法论与教训**——为什么这么调、走过哪些弯路、哪些经验可复用。

## 0. 问题域

| 检测 | 输入 | 输出 | 实现 |
|---|---|---|---|
| 图例区 | 图纸/截图 | 色板条带矩形（或 null=无图例） | `legend_detect.dart` `detectLegendCanonical` |
| 主体区 | 图 + 格距 | 豆板图案包围盒 | `restore_page.dart` `_autoDetectSubject` |
| 列序尺 | 图 + 板底位置 | 尺带顶 y（板底硬边界） | `board_detect.dart` `detectRulerTop` |

输入是三类来源：微信聊天截图（1440 宽基线）、手机翻拍照片（偏糊/偏色）、
设计图导出。共同结构：`主体（豆板网格）→ 列序尺 → 图例 → 页脚`。

## 1. 基础设施方法论（最重要的复用资产）

1. **PIL 复刻先行，单一真相源**：规则先在 `.test/wx_replica6.py`（PIL）
   上迭代——解释器里改一行跑全 fleet 是秒级反馈；定稿后才移植 Dart。
   移植不是终点：**移植后必须用同一张图的像素喂两边对拍**（本次 u1
   排障就是把 Dart 解码像素 dump 成 PNG 再喂回 PIL 复刻，一次实验证明
   移植无 bug、锅在解码器）。
2. **三解码口径**：PIL(libjpeg-turbo) / 纯 Dart image 包 / Skia(引擎，
   app 真实路径)对同一 JPEG 产出**不同像素**。三个口径 = `wx_replica6.py`
   / `dart run tool/legend_sim.dart` / `flutter test
   test/legend_skia_sim_test.dart`。app 用的口径（Skia）必须绿，其余口径
   用于交叉定位（wx2 纯 Dart 解码直接崩、u1/wx5 像素漂移，都靠口径差定位）。
3. **行特征探针**（`row_probe6.py`/`ruler_probe.py`）：打印任意 y 区间每
   行的游程特征（块数/长度/非白比/饱和色数/跨度），失败案例先解剖再动
   规则——所有阈值都应有实测数字背书，不拍脑袋。
4. **fleet 回归 + 标注图确认真值**：11 张常备图任何规则改动全量跑；候选
   框画上原图（`annotate_q.py`）让用户逐图确认，**用户确认过的框就是
   真值**，回归时直接比对数字。
5. **规则改动写"为什么"**：每条阈值旁注明触发案例（u2-1386、wx3-1498
   这种坐标编号），半年后看规则列表才能知道哪条能动哪条不能动。

## 2. 图例检测演进（v1→v9，一周 9 版）

核心方法始终是**逐行游程扫描**（RGB>>4 nibble 量化，12px 游程=图例色
片特征），演进全在"行原型怎么定、带怎么聚、假阳性怎么杀"：

| 版本 | 触发案例 → 规则 | 教训 |
|---|---|---|
| v1 | 纯白判定漏灰底图 → 近白含平灰（nibble≥11 且极差≤1） | "白"是先验不是常量：微信图纸用 ~187-214 平灰做版底 |
| v4 | 页边框整行非白 → 贴行缘游程完全剔除 | 先洗数据再提特征 |
| v5/v6 | 游程单档 20px 挡掉小色片 → 8/12 双桶 + 饱和色打分 | 图例本质=饱和色板，饱和色数把色板和灰文字拉开一个量级 |
| v7 | 画稿碎片带伪装高分 → 主体传播 + quiet 闸 + 向下延续走 | 带间结构（谁在谁上方）比带内分数更有区分度 |
| v8 | 框顶吃进列序文本 → 带顶低饱和修剪；顶垫边误吞基线 → 只看 t-2 行 | 自适应规则要找"最小充分条件"，查太宽就误伤 |
| v8.1 | B 原型补三闸救 u1 画稿行 | 见 §3.1——方向错了，加闸是错上加错 |
| v9 | u2/wx5 "顶部超出到豆板" → **删 B 原型** + quiet 放宽 0.35 + 跨度下限 + 薄带上行走 | 见 §3.1/§3.2 |

v9 定稿 11 张 fleet 全对（用户逐图确认），wx4 无图例正确返回 null。

## 3. 跨案例教训

### 3.1 规则救不了错误真值——u2/wx5 的"全宽色条"

v8 时代 u2/wx5 底部 1386 行的全宽色条（42 块、仅 2 色）被当图例真例，
为它维护了三道闸门的 B 原型；v8.1 又给 B 加 `maxLen12>=20` 排 u1 画稿
行——在错误真值上叠规则，越叠越脆。用户指出"顶部超出到豆板"后重新
看图：1386 是**豆板底排豆子**（图案条纹行），真图例是其下方 1440-1475
的色片表格。删掉 B 原型，u2/wx5/wx4 三张同时变对。

**教训**：规则和真值打架时，先怀疑真值标注（用标注图找用户确认），
别急着加闸门。"为某个案例加的规则"要能说出**这个案例为什么是真的**。

### 3.2 阈值翻转的蝴蝶效应——u1 的 2px

同一张 u1，PIL 解码图例带 1294-1318（24px，不触发薄带上走），纯 Dart
解码 1296-1316（20px，触发），上走又没有距离上限，一路爬 164px 把板底
暗影全吞进框。根因是**解码器像素差 ±2px 翻转了 `<24px` 判定**。两层修：
上走加 40px 距离上限（规则加固——收编的是"紧贴"文字行，u2 实测 22px，
任何超 40px 的行走都是越界）；解码改 Skia 优先（口径根治）。

**教训**：离散阈值附近的判定（薄带、闸门）对解码噪声极敏感；行走类
规则（延续走/上走）必须有硬距离上限，"弱墨保持"会穿越大范围稀疏噪声。

### 3.3 缩放是破坏性操作——wx1@1440 巨带

1920 宽的 wx1 缩到 1440 后全图连成一个 tall 巨带吞掉图例（null）。解剖：
豆板格线 ~3px 被 LANCZOS 涂掉，板内 bead 游程两两合并越过 12px 桶，原本
把板体切成多带的格线行（native nB12=0）集体过行原型 A。**行级无解**
（图例行本质就是"多 12px 游程多色"，与合并后的板行同签名），只有带
结构能区分，而缩放恰恰毁了带结构。

**教训**：归一化不是免费午餐。解法=**native 优先窗口 [1000,2048]**
（主流截图宽 1080-1920 全部 native 验证通过），只有极端尺寸才缩放；
3×3 中值滤波救不了系统性纹理丢失（试过，无效）。

### 3.4 解码口径本身是"参数"——Skia 优先

纯 Dart image 包 JPEG 解码器实证劣质：wx2 直接抛 Unknown marker、wx5
浅色色片解码偏亮被判白（右侧 1/4 图例丢失）、u1 像素漂移。三者换
libjpeg-turbo 口径（PIL/Skia 同源）全部正确。`decodeImageRobust` 从
"纯 Dart 优先"反转为"**Skia 优先 + 纯 Dart 回退**"（回退保留给无引擎
的测试/CLI 环境）。

**教训**：调参基准（PIL）和线上口径（Skia）不一致时，永远以线上为准，
且要证明两者同源；"能解码"≠"解得对"，解码器也是需要验证的依赖。

### 3.5 位置先验强于特征强度——列序尺 120px 窗

列序尺行签名（≥40 个微小同色游程横跨 88% 宽）在画稿区有 6 处假阳性
（u1 天空碎纹、test_pic5 图纸底纹），加再多特征也难分。但列序尺**必然
贴着图例/板底**（fleet 真例距 scanBottom 4-32px，假阳性 268px+）——
`scanBottom 上方 120px 窗`一条规则全灭假阳性。

**教训**：几何位置先验（尺在板底、图例在主体下方）往往比像素特征更
强的分类器；特征找召回，位置窗管精度。

### 3.6 防伪规则要针对生成机制——格线假阳性

白豆板的"格线残段行"与尺行同签名（微小/同色/等距/全宽），任何行内
特征都分不开。但其**生成机制**决定：白豆行上下必贴横贯格线——候选行
±6px 邻行存在 ≥0.5w 长游程即否决。按"假阳性是怎么产生的"设计否决
条件，而不是继续堆行内统计量。

### 3.7 无 OCR 的结构代理——"从 1 递增同色数字"

用户规格"从左到右从 1 开始连续递增、同色"。无 OCR 验不了数值连续性，
代理=可验子集：同色（主色覆盖 ≥85%）+ 密集微小游程（42 列板实测 56-71
个，数字碎笔画）+ 全宽跨度 + 薄带 + 位置窗。**把语义规格翻译成像素
可验特征时，逐条标注哪些验了（同色）、哪些没验（递增性）**，没验的
部分靠位置先验兜底。

## 4. 经验迁移：豆板边界 → 主体检测

列序尺经验接入 `_autoDetectSubject`：原实现 scanBottom=图例带顶，图例
漏检（wx4 类无图例图）时=图底，尺下方的页脚/导航条会泄进主体 bbox。
尺顶给出了**不依赖图例的板底硬边界**（`detectRulerTop`，只在
scanBottom 上方 120px 窗内找）。fleet 验证：有尺 4 张全中（u2/wx5=1420、
wx3=1476、test_pic5=1664），无尺 5 张零误报。

可继续迁移的方向（未实施）：图例检测的"带结构 + 位置传播"思路用于
主体簇选择（当前按内容量最大取簇，画稿比豆板大时会选错）。
