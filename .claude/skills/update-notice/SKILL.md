# 更新公告模板(每版必用)

> 本模板由 v0.2.0 公告四轮返工定稿(2026-11-09),**每版都按这个样子做**,不要再退回平铺文字或过程叙事。

## 成品与工具

| 物件 | 位置 | 说明 |
|------|------|------|
| 公告长图 | `dist/更新公告_v{版本}.png` | 2160 宽长图,生成器 `scripts/gen_update_notice.py` |
| 公告文字版 | `dist/更新公告_v{版本}.md` | 与图同内容,给能看 md 的渠道 |
| 生成命令 | `python scripts/gen_update_notice.py` | 改脚本内版本数据(标题/徽标/STATS/FEATURES/定名卡文案)后重跑 |

## 长图版式(自上而下,v4)

1. **头图 700px**:米色底 + 96px 图纸格纹理;居中圆形自适应图标(330,`adaptive_circle`);大标题「豆田 vX.Y.Z」(96 粗体,`anchor='ma'`);下方白底绿描边徽标胶囊「版本性质 · N 项改进 · 日期」。
   ⚠ 标题底部与徽标顶**净距 ≥30px**,v3 曾压叠被用户点名;改字号必须重新量。
2. **主题卡 350px**:整版图标(230)+ 卡片标题(62 粗)+ 三行说明。放定名/换图标这类"门面"大改。文案要平实:**不写设计比喻**(如"豆苗从格线里长出来"被否),**不写开发者视角**(如"槽形自适应"被否)。
3. **亮点数据块 ×4(330px)**:白卡 + 上下细绿条点缀;大字结论词(84 粗,绿,如 更快速 / 自定义显示 / 无损 / 免登录)+ 一行粗标题(38)+ 一行灰说明(34)。
   ⚠ 大字用**结论词**而非裸数字(用户定稿:37 秒→更快速、2~16 格→自定义显示),具体数字放说明行;不许用「15 项」这类凑数块——用户明确嫌过丑且表意不清。
4. **功能卡若干**(白圆角卡):左上绿色编号章(01/02…,64 方块)+ 卡标题(60 粗);条目为**双列小卡**(TILE_BG 底圆角 20):
   - **emoji 图标**(40,`Segoe UI Emoji` + `embedded_color=True` 出彩色,居中于条目头行)+ 粗体标题(46)+ 灰色说明(40 自动换行);
   - 末条奇数自动通栏(`span` 逻辑);
   - 条目多时(>4)卡内自然两列排,不要退回列表圆点。
5. **不放安装说明**——用户明确要求去掉;安装口径只在 md 里保留。

## 内容边界(防把已公告过的内容再写一遍)

- **上一版边界**三处对账,必须一致:
  1. `CHANGELOG.md` 最顶 `## [x.y.z] - 日期` 段 = 上一版已发布内容全清单,公告与之一一对应;
  2. `git log --grep='^release(v' -1` 找上一个发布提交,`git log <该提交>..HEAD --oneline -- lib android assets pubspec.yaml` = 之后真正的 app 改动(公告/skill/文档提交自然排除);
  3. `dist/更新公告_v*.md` 旧版存档只读不改——已出现在旧公告的条目一律不进新公告。
- 新公告内容 = CHANGELOG 新版本段(从未发布段归位而来),只收录**上一版边界之后**的提交;没进 CHANGELOG 的改动不写公告。
- 动笔前先跑一遍上面第 2 条把增量提交列全,逐条判断「用户可感知 且 未公告过」再组织进 STATS/FEATURES。

## 内容规矩(返工教训,勿再犯)

- **只讲最终结果**,不写设计/迭代过程(「13 稿 5 轮」「从 A 改到 B」这类一律不要)。
- 条目标题 = 短粗体**结论**(如「空白格不虚涨」),说明 = 一句话讲清用户受益。
- 数据块必须表意完整:大字结论词 + 两行完整句子,不做孤立数字。
- 图标语义对位:🧹 清虚涨 / 🔍 补认 / ⚡ 不崩 / 📊 进度 / 🖐 拖选 / 🔢 列数 / 🧮 计数 / 🔒 锁定 / 🖼 原图 / 🔗 链接 / 🗂 豆板 / 🎚 步长 / 🛡 防误触。

## 技术要点

- 字体:`assets/fonts/NotoSansSC-{Regular,Bold}.otf`;emoji 用 `C:/Windows/Fonts/seguiemj.ttf`(彩色需 `embedded_color=True`;🔗/📎 是灰色属正常)。
- 常量:W=2160, MARGIN=96, PAD=70;配色 BG 米 / GREEN 主绿 / TILE_BG 小卡底,见脚本头。
- **`measure()` 必须与 `draw_board()` 同步改**,高度 = 各段高 + 46 间距 + 80 底边距。
- 校验(改版式后必做,禁用肉眼看截图下结论):PIL 逐项查——头图标题底行 vs 徽标顶净距、每张功能卡 emoji 着色像素、结尾纯背景、总高与 measure 一致、新文案行宽不越界;然后 `code -r` 给用户看。

## 每版发布完整流程

1. `pubspec.yaml` bump 版本 → `CHANGELOG.md` 新版本段(Keep-a-Changelog:新增/改进/修复,只写用户可感知的变化)。
2. `flutter build apk --release`(必须全架构,dist 交付规矩)→ 覆盖 `dist/bead_studio_v{版本}.apk`,记录字节数/md5。
3. 复制上一版 `gen_update_notice.py` 数据区(标题版本号、徽标文案、主题卡、STATS、FEATURES)按本版改动重写,跑生成 + PIL 校验 + `code -r`。
4. 写 `dist/更新公告_v{版本}.md`(文字版,结构对应:导语 → 主题段 → 各功能段 → 安装说明段)。
5. `project-status.md` 交付表加一行;提交信息 `release(v{版本}): …`。
